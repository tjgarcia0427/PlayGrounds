Executive decisionPlaygrounds v0.2

Make collaboration conditional, measured, and reversible

v0.2 is not “more agents.” It is a control system that selects the cheapest reliable topology for each task, records why it made that choice, verifies the result, and learns from the outcome.

Build now

One orchestrator owns the shared truth

  • A durable task ledger holds the plan, constraints, dependencies, and acceptance criteria.
  • An append-only progress ledger records assignments, evidence, stalls, decisions, and replans.
  • Workers receive bounded task envelopes and return structured artifacts, not unbounded group-chat prose.
Change the default

Solo first; fan out only on evidence

  • Every task starts with a solo candidate.
  • Parallelism requires high decomposability, low dependency coupling, and a positive expected utility after coordination cost.
  • Each playground has four registered agent slots, enforced at registration; the control-plane orchestrator is not a hidden fifth participant.
Research boundary. In a matched-compute study of 260 configurations, multi-agent performance ranged from +80.8% on decomposable financial reasoning to -70.0% on sequential planning. The reviewed evidence favors tightly scoped 2–4-agent teams over larger, coordination-heavy groups; centralized verification also contained error propagation better than independent aggregation. [1][5]

v0.2 release outcome

A private pilot can accept a goal, decompose it into typed tasks, discover agents by Agent Card, choose solo or a small specialist team, stream ledger events, collect typed artifacts, run deterministic and human verification, settle internal credits, and update capability-specific routing and reputation models.

Explicitly out of scope

Public marketplace
No anonymous discovery or open enrollment.
Cash redemption
Credits remain non-cash internal accounting.
Avatar implementation
Define the workstream now; animate only after platform refinements.

Migration rule

Dual-read, single-write

Read v0.1 records during migration, but write only v0.2 schemas. A one-time migration emits canonical ledger events and retains the original JSON as a read-only backup.

Compatibility rule

Adapters stay thin

REST, MCP, and A2A translate into one internal command model. Business rules live in the core, not in connector-specific handlers.

Do not extend the current model-tier table. Declared model strings are not evidence of task fit. Keep them for observability and cold-start priors only; route on verified outcomes as soon as data exists.

Research to productEight implications · 1 of 2

The research becomes operating rules, not decoration

Each implication below maps to a visible system behavior and a testable gate.

Rule 1

Start with one agent

Behavior: The topology selector evaluates solo first. Multi-agent execution must beat a solo baseline on expected verified utility after cost and latency.

Gate: no task may fan out without recorded decomposability, coupling, budget, and expected-uplift fields.

Rule 2

Use a central orchestrator

Behavior: One lead owns plan, assignment, state transitions, integration, stopping, and replan. Workers do not mutate the global plan.

Gate: every state transition has one authoritative actor, previous version, and idempotency key.

Rule 3

Move facts through ledgers and artifacts

Behavior: Messages can notify, but decisions, evidence, blockers, and outputs become typed records. The system can replay a run without reading free-form chat.

Gate: 100% of completed tasks have a valid output contract and at least one immutable artifact or explicit “no artifact” result.

Rule 4

Learn routing from outcomes

Behavior: Estimate acceptance, quality, latency, and credit cost per task-agent pair. A transparent utility function chooses candidates; static tiers only seed cold start.

Gate: the learned router must win a held-out comparison against v0.1 before it controls assignments.

Evidence: architecture-task alignment [1], routing from preference data [6], structured delegation [5].

Research to productEight implications · 2 of 2

Trust and economics share the same evidence spine

Rule 5

Verification is a first-class workflow

Behavior: Deterministic checks run before judgment. Reviewers receive the task contract, artifacts, provenance, and check results. High-risk work requires a human.

Gate: no payout, reputation change, or router label exists without a verification receipt.

Rule 6

Reputation updates only outside a deadband

Behavior: Maintain capability-specific posterior scores. Ambiguous, low-confidence, or weakly attributable outcomes are recorded but do not move reputation.

Gate: one low-confidence rejection cannot materially change an established agent’s score.

Rule 7

Credits follow marginal verified contribution

Behavior: Pay for accepted utility added to the integrated result, not time, tokens, message count, or self-reported effort. Redundant artifacts earn little or nothing.

Gate: settlement shares reconcile exactly to escrow and include an auditable rationale.

Rule 8

Separate A2A, MCP, and trust policy

Behavior: A2A describes and exchanges agent tasks; MCP remains the agent-to-tool boundary. Playgrounds adds identity, authorization, tenant isolation, audit, and policy.

Gate: no Internet exposure until every public-launch control on page 13 passes.

Core principle: an Agent Card is a claim. Only observed, verified outcomes may become reputation or routing evidence.

LedgersPlan outside the prompt

Two ledgers make progress inspectable and recoverable

Magentic-One separates a task ledger from a progress ledger and replans when work stalls. Playgrounds should adopt the pattern as durable state, not model-only scratch text. [4]

Task ledger: what must become true

  • Goal contract: objective, owner, success criteria, constraints.
  • Task graph: dependencies, milestones, risk, topology policy.
  • Input contract: typed parts, provenance, sensitivity.
  • Output contract: schema, media types, evidence minimums.
  • Economics: budget, bounty, escrow, maximum cost.
  • Authority: assignee, verifier, required approvals.

Progress ledger: what happened

  • Event: actor, timestamp, idempotency key, prior version.
  • Status: submitted, working, blocked, input required, terminal.
  • Evidence: artifact IDs, check results, provenance links.
  • Decision: route score, selected topology, overrides.
  • Recovery: retries, stall reason, cancellation, replan.
  • Accounting: reservation, settlement, reversal receipts.

Replan trigger: no decision-changing progress across two checkpoints, a dependency changes, the selected agent breaches its lease, or verification fails with a recoverable reason. The orchestrator records the reason before creating replacement work.

Agent Cards turn capabilities into versioned contracts

A2A provides discovery, task, message, part, artifact, and streaming semantics for opaque agents. MCP remains a host-controlled tool interface with one client per server. The two protocols solve different edges. [7][9]

Playgrounds keeps claims separate

  • Declared profile: card version, skills, endpoints, modes, limits, security schemes.
  • Observed profile: acceptance posterior, verified quality, latency, spend, timeout rate, evidence quality.
  • Policy overlay: tenant allowlist, allowed task classes, tool scopes, maximum bounty, trust zone.
Never overwrite one with another. A provider may update a card; observed performance remains Playgrounds-owned history tied to agent identity and skill version.

Learned routingReplace model-name tiers

Predict verified utility, then expose the reason

RouteLLM shows that preference-trained routing can lower cost while preserving quality; Playgrounds should apply the same principle to agent selection using its own verified task outcomes. [6]

Feature contract

Task
type · required skills · difficulty · decomposability · coupling · tool intensity · risk · deadline · budget
Agent
card skills · skill version · availability · observed quality · latency · timeout · cost · trust zone
Interaction
skill overlap · prior task similarity · owner preference · tool compatibility · context fit

Decision function

expected_utility(agent, task) =
    p(accepted) × expected_quality × task_value
  − expected_credits
  − latency_weight × expected_latency
  − risk_weight × failure_cost
  − coordination_cost(topology)

Learning path

1
Log the v0.1 baseline.
Store every heuristic suggestion, selected agent, override, outcome, cost, latency, and verifier confidence.
NO CONTROL
2
Train an interpretable pairwise model.
Start with regularized logistic acceptance + separate latency/cost estimators. Use time-split validation to prevent leakage.
OFFLINE
3
Run in shadow mode.
Return learned rankings beside heuristic rankings, but do not assign. Measure regret and calibration.
OBSERVE
4
Allow opt-in assisted routing.
Human confirms the top choice; overrides become preference labels, not automatic failures.
APPROVE
5
Autopilot low-risk tasks only.
Require a passed held-out gate and retain rollback to heuristic or manual assignment.
LIMITED
Cold start: use v0.1 heuristics as priors, with explicit uncertainty. Do not pretend a model family is a stable capability ranking. Route exploration deliberately, cap its budget, and never explore on high-risk tasks.

Decision pseudocode

candidate = SOLO
if task.decomposability >= 0.70
   and task.coupling <= 0.30
   and objective_verifier_available
   and expected_team_utility >= expected_solo_utility × 1.10:
       candidate = SEALED_SCOUTS or SPECIALIST_DAG
candidate.team_size = min(predicted_optimal_size, playground.open_slots, 4)
assert playground.registered_agent_count <= 4
require human approval when risk >= HIGH or uncertainty >= 0.25
Communication policy: workers send structured evidence deltas to the orchestrator. Peer-to-peer chat is disabled by default. AgentPrune found large token reductions from removing redundant communication edges, supporting sparse rather than social coordination. [3]

Deterministic checks first

  • Output schema and required fields
  • File integrity, digest, media type, size
  • Executable tests or exact-match validators
  • Policy, permission, provenance, and budget checks
  • Duplicate or near-duplicate artifact detection

Human or model review second

  • Rubric-scored correctness and usefulness
  • Evidence coverage and unresolved uncertainty
  • Attribution by artifact and contributor
  • Confidence score and reason codes
  • Escalation path for disagreement

Receipt schema

  "verification_id": "ver_…", "task_id": "task_…",

  "deterministic_checks": [{"id":"tests", "result":"pass"}],

Reviewer comments are evidence to investigate, not proof by themselves. c-CRAB found current review agents collectively solved only around 40% of its held-out-test tasks, so executable checks stay authoritative wherever available. [11]

Reputation & creditsReward signal, absorb noise

One receipt drives two distinct ledgers

Trust signal

Capability-specific reputation

For each agent × skill × task_type, maintain a Beta posterior with neutral prior Beta(2,2). Weight updates by verifier confidence and recency; show the interval and effective sample size, not only a point score.

Provisional deadband:

  • Quality ≥ 0.75 and confidence ≥ 0.75: positive update.
  • Quality ≤ 0.35 and confidence ≥ 0.75: negative update.
  • Between thresholds, unverifiable, or low confidence: record only; no directional update.

These thresholds are initial policy, to be calibrated from pilot disagreement data.

Economic signal

Marginal-contribution settlement

Reserve the bounty in escrow. After acceptance, split it into:

  • 90% work pool allocated by verified marginal contribution.
  • 10% review/integration pool paid only to eligible independent reviewers or integrators.

For teams of four or fewer, estimate each contribution by leave-one-out evaluation:

delta_i = max(0, V(all) − V(without_i))
share_i = delta_i / sum(delta)

If evidence cannot isolate a contribution, send the task to human settlement and do not auto-learn from the split.

Anti-gaming invariants

AttackControlLedger effect
Duplicate workSimilarity + provenance checkNear-zero marginal credit
Self-reviewIdentity-aware separationSettlement rejected
Message spamNo pay for messages/tokensRate-limit event only
Easy-task farmingTask value + difficulty strataReputation remains per capability
Reviewer collusionConflict rules + audit samplingHeld settlement; trust review
Do not convert credits to money in v0.2. First establish abuse rates, dispute handling, accounting semantics, and legal/tax implications.

Trust boundaryPrivate pilot before public surface

Public exposure is a release gate, not a deployment step

A2A enables interoperability without sharing internal memory or tools, but it does not supply Playgrounds’ cross-owner authorization, tenancy, credit policy, or audit model. Those are the product’s trust layer. [7][8]

Identity and authorization

User authentication and verified ownership of each agent.
Per-agent asymmetric key; short-lived tokens bound to tenant, audience, and scopes.
Scopes for goal read/write, task claim, artifact publish, verify, and settle.
Minimal public card; authenticated extended card for sensitive skills and endpoints.
Revocation, rotation, device/session inventory, and emergency kill switch.

Execution and data

Per-task sandbox with isolated filesystem and bounded CPU, memory, wall time, and output size.
Default-deny network egress; explicit destination/tool allowlists.
Tenant-scoped storage and encryption; no cross-tenant object references.
Artifact malware/content scanning before another agent can consume it.

Prompt-injection containment

Treat every remote message, card, tool result, and artifact as untrusted data.
Never let remote text rewrite system policy, scopes, routing rules, or approval requirements.
Pass only task-minimum context; redact unrelated user memory and credentials.
Validate structured fields independently of natural-language content.

Operations and abuse

Per-tenant and per-agent rate, concurrency, spend, and artifact quotas.
Immutable audit receipts with actor, scope, decision, and content digest.
Replay-safe idempotency keys and signed webhook/push events.
Threat model, abuse tests, incident runbook, backup restore, and dependency inventory.
Public-launch gate: every checkbox above passes automated or documented review; cross-tenant negative tests show no data access; all mutating routes enforce scopes; a third-party security review has no unresolved critical/high findings.

Evaluation matrix

Sequential tasks
Expect solo to win. Tests prevent fan-out enthusiasm from becoming policy.
Decomposable research
Compare solo with two and four sealed scouts; measure unique evidence and cost.
Dependency-heavy builds
Compare solo with isolated specialist DAG; measure conflicts, rework, and test pass rate.

Minimum pilot sample

Do not promote the learned router until at least 100 verified tasks span three task types and at least three agents, with a time-ordered holdout. If the sample is smaller, v0.2 still ships with ledgers, A2A, verification, and shadow recommendations; routing remains manual or heuristic.

Targets are hypotheses, not results. The first pilot exists to calibrate thresholds for topology, deadband, router uncertainty, and contribution scoring. Preserve raw receipts so every threshold can be recomputed.

Definition of doneOwner-ready checklist

The v0.2 handoff is executable without hidden decisions

Product behavior

New goal creates a versioned plan and success criteria.
Every task has typed input, output, evidence, risk, and dependency fields.
Topology selector records solo/team decision and counterfactual.
A fifth registration returns HTTP 409 across every registration adapter; the dashboard agrees with server capacity.
Orchestrator detects a stall and can cancel or replan.
Agent Card discovery and one real A2A task round-trip pass.
Existing MCP test remains green through the adapter.
Dashboard renders live plan, progress, verification, and settlement events.

Evidence and economics

Artifact digests and provenance survive replay.
Verifier receipt gates reputation, labels, and payout.
Deadband leaves ambiguous outcomes neutral.
Contribution shares reconcile to escrow exactly.

Operational safety

All mutating commands are idempotent and authorized.
Tenant isolation and object-level authorization tests pass.
Rate, spend, concurrency, and artifact limits are enforced.
Untrusted agent content cannot alter policy or tool scopes.
Backup restore and event replay reproduce the same state.

Decision at the end

Promote: if verified utility per credit improves and all trust gates pass.

Hold: if quality improves but the cost or security envelope does not.

Roll back: if learned routing or multi-agent execution fails to beat the solo/v0.1 baseline under matched budgets.

Recommended first build: Increment 0 + Increment 1 together. The ledger and artifact contract create the training data, auditability, and migration safety needed by every later feature.

Assumptions made for this plan

The v0.2 pilot remains private and invitation-only; credits remain non-cash; the core stays Python-based; each playground has a standing ceiling of four registered agents; JSON-RPC + SSE is the first A2A binding; the existing dashboard remains the operator surface; avatar implementation begins only after the platform refinements; and thresholds are provisional until pilot data calibrates them.

Avatar and animation workstreamPhase after platform refinement

Give each agent a soft body and a clear operational state

The visual direction fuses the polished, responsive feel of the Muse assistant avatar with an original stuffed-animal/chibi character system. This is a design target, not an asset copy: Playgrounds should borrow the sense of presence and motion quality while keeping its own silhouettes, materials, expressions, and identity.

Character language

Soft, collectible, unmistakably readable

  • Oversized head, compact body, rounded paws, and a strong silhouette at dashboard scale.
  • Plush or felt material cues, subtle seams, restrained highlights, and one capability-linked accent.
  • Face stays minimal: eyes, brows, and mouth carry state without becoming noisy.
  • Every agent remains identifiable in grayscale and at a small tile size.
Motion language

Ambient life, elastic response, calm restraint

  • Idle: slow breathing, tiny weight shift, occasional blink.
  • Thinking: focused gaze, gentle hover or bob, contained pulse.
  • Working: purposeful loop tied to progress, never random busyness.
  • Blocked: softened posture and a clear pause signal, not distress theater.
  • Done: brief squash-and-stretch acknowledgement, then return to idle.
